# Compass · 아스트라 3D 탐험 나침반

고대 유물 모양의 3D 나침반으로 방향을 살펴보고, 8방위 보물 미션을 즐기는 웹앱입니다.
휴대폰에서는 센서를 연결하고, PC나 센서 미지원 환경에서는 수동으로 탐험합니다.

- 버전: **v1.0.1**
- 기준 소스: 제공된 `3d-2.html`
- 배포 방식: **GitHub Pages · 정적 파일 · 별도 서버 없음**
- 공개 상태: 공개 저장소 생성과 GitHub Pages 배포 완료.
- 저장소: https://github.com/PoeticEcho/compass
- 앱 주소: https://poeticecho.github.io/compass/

## 1. 주요 기능

| 기능 | 내용 |
| --- | --- |
| 2D 호환 화면 | WebGL 미지원 시 자동 전환. 방향·센서·미션 유지 |
| 3D 나침반 | 원형 눈금판·방위 바늘·유물 장식·입자 효과 |
| 센서 방위 | iOS 나침반 또는 절대방위 이벤트 사용. 상대 회전 이벤트는 제외 |
| 수동 탐험 | 드래그·휠·슬라이더·8방위 버튼·자동 탐험 |
| 보물 미션 | 목표 방위 ±10° 안에서 유물 발견, 8방위 탐험 |
| 세 가지 테마 | 황금 유물·아틀란티스·별자리 |
| 효과음 | 기본 음소거, 사용자가 선택하여 활성화 |
| 내 위치 | 선택적으로 위도·경도·위치 정확도를 표시 |
| 소개 페이지 | 사용법·센서와 수동 모드의 차이·개인정보 안내 |

## 2. 사용 순서

1. HTTPS로 공개된 앱 주소를 Chrome 또는 Safari에서 직접 엽니다.
2. `센서로 시작`을 누르고 권한 요청이 뜨면 허용합니다.
3. 휴대폰을 수평에 가깝게 유지하고 화면 위쪽이 향하는 방위를 봅니다.
4. 센서를 사용할 수 없으면 `수동으로 탐험하기`를 선택합니다.
5. `보물 미션 시작`으로 목표 방향을 맞추고 봉인을 해제합니다.

수동 조작은 센서 추적을 중지합니다. 실제 방향으로 돌아가려면 `센서 연동 → 센서 연결`을 누릅니다.
위치는 필수가 아닙니다. 위치 좌표와 이동 방향으로 나침반 방향을 추정하지 않습니다.
앱이 백그라운드로 전환되면 위치·센서 추적을 멈추며, 복귀 후 다시 연결합니다.

## 3. 방위 표시 기준

- 화면의 고정된 `기기 앞쪽` 표시는 기기 화면 위쪽 방향입니다.
- 센서 모드의 숫자는 브라우저가 제공하는 기준 방위입니다.
- **지자기 모델에 의한 진북 보정은 적용하지 않습니다.** 센서별 북쪽 기준의 차이가 있으므로 진북 정확도를 보장하지 않습니다.
- iOS는 유효한 `webkitCompassHeading`을 우선 사용합니다.
- 표준 이벤트는 `absolute === true`인 `alpha/beta/gamma`만 사용합니다.
- 표준 이벤트는 기기 상단 벡터를 수평면에 투영해 방위를 계산하며, 거의 수직인 모호한 자세는 제외합니다.
- 화면 회전각을 반영합니다. 실제 기기에서 세로·가로를 바꾸어 검증해야 합니다.
- 원본의 임의 고정 편각 및 전 세계용 사인 함수 편각 추정을 제거했습니다.
- 센서 신호가 5초 이상 끊기면 마지막 방위임을 표시합니다.
- 수동 탐험 숫자는 가상 방위이며 실제 북쪽을 측정하지 않습니다.
- 공명도·수호신·유물은 게임 표현입니다. 자기장 세기·센서 정확도 수치가 아닙니다.

| 파일 | 역할 |

| `assets/THREE-LICENSE.txt` | Three.js MIT 라이선스 고지 |
| `tests/compass.test.cjs` | 방위 계산·센서 취소·위치 분리 회귀 검증 |
| `docs/REVIEW.md` | 원본 분석·수정 사항·미검증 범위 |

별도 API 키·백엔드·DB·빌드 서버가 없습니다.
Three.js와 CSS를 배포본에 포함했으므로 런타임 Tailwind CDN은 사용하지 않습니다.
Google Fonts는 외부에서 불러오며 실패하면 기본 글꼴로 표시합니다.

## 5. 로컬 실행 및 수정

배포본은 이미 준비되어 있어 설치나 빌드 없이 정적 웹서버로 열 수 있습니다.

```bash
python3 -m http.server 8000
```

`http://localhost:8000`에서 수동 탐험을 확인합니다.
휴대폰의 센서·위치는 HTTPS 공개 주소에서 검사합니다. 다운로드한 HTML을 파일 앱으로 여는 방식은 권한 제한을 받을 수 있습니다.

Node.js가 있으면 계산과 권한 처리 검증을 실행할 수 있습니다.

```bash
npm test
```

HTML 클래스나 사용자 스타일을 바꾼 경우 CSS를 다시 생성합니다.

```bash
npm install
npm run build:css
```

Tailwind는 개발 도구이며, 배포 후 방문자 브라우저에서 실행하지 않습니다.
`assets/app.js`에서 동적으로 만드는 클래스도 CSS 생성 대상입니다.

## 6. GitHub Pages 공개

1. GitHub에서 **공개 저장소 `compass`**를 만듭니다.
2. 이 폴더의 내용물을 저장소 최상위에 올립니다. `index.html`이 최상위에 있어야 합니다.
3. `Settings → Pages → Build and deployment`로 이동합니다.
4. Source에서 `Deploy from a branch`, Branch에서 `main`, 폴더에서 `/(root)`를 선택하고 저장합니다.
5. Pages 배포가 완료되면 GitHub가 표시한 실제 주소를 확인합니다.

Pages 기능은 저장소·계정 정책에 따라 관리 권한이 필요합니다.
수정한 파일을 `main`에 올리면 Pages가 갱신합니다.
`main` 브랜치 최상위에서 GitHub Pages로 배포하고 있습니다.

## 7. 검증 결과와 남은 확인

| 항목 | 결과 |
| --- | --- |
| JavaScript 구문 검사 | 통과 |
| 방위·권한·취소·GPS 분리 자동 검증 | 8개 통과 |
| DOM ID 참조 및 로컬 자산 경로 | 통과 |
| 배포용 CSS 생성 | 통과 |
| 데스크톱 2D 호환 화면·방위 버튼·테마·미션 | 공개 주소에서 확인 완료 |
| 3D 렌더링·작은 모바일 화면 | 실기기 확인 필요 |
| Galaxy S25+·iPhone 실센서 | 미실행 |
| GitHub 저장소 업로드·Pages 배포 | 완료 |

실기기 확인 항목:

- 수평 상태에서 N/E/S/W를 휴대폰 기본 나침반과 비교합니다.
- 세로·가로 화면 전환 시 기준 방향을 확인합니다.
- 센서 권한 허용·거부·재요청 및 신호 중단 안내를 확인합니다.
- 위치를 켜도 방위가 덮어써지지 않는지 확인합니다.
- 수동 조작 후 기기를 돌려도 방위가 덮어써지지 않는지 확인합니다.
- 화면 숨김·복귀 시 센서와 위치가 중지되는지 확인합니다.
- 작은 모바일 화면에서 나침반·미션·조작부가 겹치지 않는지 확인합니다.

**현재 결론:** 원본의 방위 신뢰성을 떨어뜨리는 로직은 수정했고 자동 검증은 통과했습니다. 실제 기기 정확도와 화면 품질까지 문제가 없다고 확정한 상태는 아닙니다.

## 8. 개인정보·외부 의존성

- 좌표·센서값을 앱 서버에 저장하거나 전송하지 않습니다.
- CodePen 소스 전송과 Geo-IP 조회를 제거했습니다.
- 분석 추적기·회원가입·기기 정보 업로드 기능이 없습니다.
- 위치 제공 과정은 사용자의 브라우저·운영체제 정책을 따릅니다.
- GitHub Pages와 Google Fonts는 IP 주소 등 일반 웹 접속 정보를 처리할 수 있습니다.
- 앱 원본에 별도 이용허락이 제시되지 않아 앱 전체에 임의의 오픈소스 라이선스를 부여하지 않았습니다. 공개 열람과 재배포 허락은 별개입니다.
- Three.js는 포함된 MIT 고지를 따릅니다. r128은 원본 호환성을 위해 유지했으며 최신 버전으로의 마이그레이션 검증은 별도입니다.
